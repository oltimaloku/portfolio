## The problem

Chat AI made studying feel easier and learning worse. Reading a fluent answer *feels* like understanding, but what actually makes knowledge stick is retrieval: producing the idea yourself, getting it wrong, and fixing it. A tool that hands over the answer on request quietly removes the part that teaches.

Neuron is built on the opposite premise. It's for university students in concept-heavy technical courses (CS, math, engineering, stats) and it is designed to give them **the right kind of difficulty** instead of removing it.

> Stuck? It asks a question back first.

## How a session works

A student uploads their own course material: lecture PDFs, slide decks, Word documents, readings, web pages or links. With no material at all, Neuron writes it. It reads the first lecture and the course is teachable within about a minute. From there:

1. **Goals.** Neuron sets goals for the exam from your own slides, and you work on one focus goal at a time.
2. **Quick check.** Before every lesson, one question finds where you actually are, so the lesson starts at the gap.
3. **Lesson.** Short questions, one to three sentences at a time. Hints start vague and only sharpen when you're stuck. Every claim cites the slide it came from, and the citation opens the page. If you ask to just be told, it explains directly.
4. **Wrap-up and review.** Each lesson ends on the idea that's still least clear, and a planner picks the next step. Later reviews check what you still remember.

Underneath, a concept map tracks what you can reproduce *cold*: every concept you've explained, scored against the source and scheduled for review. It's a map of what you own, not a checklist of what you read.

## The agents behind the tutor

Students only ever talk to Neuron. Behind it, specialist agents each do one job within set limits, and none of them marks its own work:

- **Perk**, the course builder, reads files and the syllabus (sections, dates, figures) and keeps the plan current as uploads arrive.
- **Oli** finds how concepts depend on each other and draws the map the tutor can bring in.
- **Pyra** judges no-help attempts against a fixed answer key, keeping *help given* separate from *recall shown*.
- **Jev** is a fast reader that classifies what kind of message just arrived in 70–500 ms, so the expensive model isn't asked questions a cheap one can answer.
- A **reading team** reads uploads: one small agent per file, run in parallel, each limited to its own folder. In a reading lab over ten open courses with hand-checked answers, it got 2.3x faster while quality held or improved.
- A **review scheduler** written in plain code (no model involved) decides when you're tested next.

## Where code makes the decisions

The most important design decision in Neuron is where the model *isn't* trusted. A turn router written in code picks the route (teach, wrap up, skip, explain, show a figure, draw a visual) before the tutor model runs. Anything countable is counted in code. Mastery levels and review dates come from rules, not from a model's opinion of itself.

Where a fast model reading *is* used, the thresholds came from data. Across 64 recorded readings, questions about the *form* of a message came back at 0.92–0.97 confidence, while questions about its *content* sat at 0.40–0.61. So Jev only answers form questions. The same analysis exposed a route whose confidence gate could never be cleared. It looked cautious, but in practice nothing could ever reach it.

## Evaluation

A tutor's quality shows in how it behaves across many conversations, so Neuron has its own evaluation system:

- **Scripted tasks**, for example *conditional vs. marginal probability*, *don't diagnose an error in a correct answer*, *cite on demand*. Each runs **k trials, each in a fresh fixture course**, graded on the event log and the files the trial left behind, and tracked across a **five-run health window** so a regression is visible the day it lands.
- **A situation benchmark**: 50 frozen teaching situations graded by an Opus judge. The judge is only trusted on a question once it has been checked against at least 30 of my passes and 30 of my fails and agrees with me on both, and results come with confidence intervals and a held-back test split.
- **A benchmark agent** that I grade with by chatting. My critiques of its examples become the judge's rules.
- **Blind A/B compares** inside the app. A change to the tutor's behaviour without a compare or an eval is treated as an anecdote.

Every experiment gets a log with its expected result written before the run. Around all of this sits a large automated test suite, including a test that walks every route of the real app to prove each one sits behind authentication.

## Cost and models

Reading a course is the most expensive thing Neuron does. Against a real run of my CPSC 340 course ($39.76 for 1,853 pages), prompt caching, skipping vision on thin title slides and a cheaper reading tier cut the cost by 37%. A blind Opus judge confirmed accuracy held.

Logging the model on every call also caught a real gap: testers were getting Sonnet on the server while every eval ran on Opus. The tutor is now pinned to the model it was tested on. Each account and session can also switch between Claude and OpenAI's Codex.

## How I build it

I build Neuron alone, mostly through Claude Code. Testers leave feedback from a tab on every screen of the iPhone app. Each note becomes a GitHub issue with a screenshot and device details, Opus reviews it within minutes, and it can run as its own Claude Code session that fixes it and opens a pull request.

An `@claude` agent on GitHub answers questions and proposes fixes. One job with read-only access writes the patch, and a separate guarded job publishes it. Skills in the repo cover verifying the app, finishing a pull request and keeping the benchmark up to date.

## Tech stack

Neuron runs as a web app, an iPhone and iPad app, and a marketing site:

- **Web:** Next.js 16, React 19, TypeScript, Tailwind. KaTeX for math, pdf.js for the slide viewer, d3-force for the concept map.
- **Backend:** Python and FastAPI over Postgres, with a Postgres-backed job queue and a separate upload worker for document extraction (Docling, PyMuPDF, Tesseract). Teaching runs on the Claude Agent SDK, with OpenAI's Codex as a per-session option. Diagrams the tutor draws are rendered with Playwright so the model can check what it drew.
- **iOS:** SwiftUI, with sketching on slides from a paired iPad, voice input and spaced review.
- **Infrastructure:** one AWS EC2 host running Docker Compose behind Caddy, on three isolated networks with non-root containers. Google OAuth with PKCE and opaque server-side sessions; only hashes of tokens are stored.

## How it started

Neuron didn't start as Neuron. In fall 2024 I built [Lupe](/projects/lupe/), a SwiftUI app for learning by explaining things in your own words, with on-device speech recognition. Lupe proved the idea and showed the limit: grading an explanation is easy, but *teaching* someone toward a better one needs memory, sources and judgement.

In fall 2025 the first real MVP was deliberately manual: an AI coding agent acting as a tutor over real material for three of my own UBC CS courses, with every failure written down. Those notes became the product rules. Lupe was rebuilt on the web with an agentic tool loop, file-based memory and click-to-slide citations, and grew into the Neuron that's in private beta today.

## Principles

- **Struggle is the feature.** It asks a question back first. Hints get sharper, not longer.
- **Terse by default.** One to three sentences. More only when you ask.
- **Never off-source.** Locked to your materials; if it isn't in your slides, Neuron says so.
- **Nothing marks its own work.** The tutor teaches, a separate judge grades, and code keeps the schedule.
